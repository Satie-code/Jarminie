## Summary

JARMINEI now actually thinks before it speaks. Every conversation turn runs through a real Decision Engine — a local Ollama LLM classifies intent, deepens it into topic/entities/sentiment/suggested persona, cross-references five layers of persisted memory (Shared, Jarvis, Minie, Event, Short-Term), weighs priority and authority, and hands the result to the persona layer as an explainable `DecisionTrace`. Replies now measurably differ from Level 2's templated placeholder whenever relevant memory or decision context exists — persona switching is driven by real Context Analysis rather than a keyword list, and a "remember this" style utterance genuinely locks a fact in at maximum confidence, permanently, via the User Override Rule. Every new failure surface this introduced (an external AI runtime, dual-backend persistence) fails gracefully rather than taking the app down.

## What Shipped

- **Memory Engine** (3.1–3.4) — `MemoryStore` (dual-backend: SQLite source-of-truth + ChromaDB semantic search) underlies all five memory layers; `PersonaScopedMemory` (Shared/Jarvis/Minie, structurally read-scoped), `EventMemory` (permanent, undeletable milestones by construction), `ShortTermMemory` (salient conversation turns promoted into scored records).
- **Dynamic Memory** (3.5–3.6) — `ConfidenceScorer` implements the full five-factor Dynamic Memory Formula and the User Override Rule (an un-overridden record caps at 80/Long-term by design); `MemoryLifecycleManager` turns confidence bands into real behavior (`run_cleanup_pass()` deletes past-grace-period Temporary records, `run_monthly_review()` surfaces Monthly-review records for a human, `apply_user_override()` persists the override).
- **Decision Engine** (3.7–3.11) — `IntentDetector` (Ollama-backed intent classification, degrading to `UNKNOWN` on any failure), `ContextAnalyzer` (topic/entities/suggested persona/sentiment), `MemoryRetrievalEngine` (ranked, explainable cross-type memory query), `PriorityQueueManager` (Part 2's full five-level priority system), `AuthorityEvaluator` (three-level authority system with a default-deny, whitelist-gated `EMERGENCY_ASSIST` — structurally unreachable until Level 4 populates real emergency procedures — plus `DecisionTrace.explain()`, the Explainability Rule's own deliverable).
- **Decision Engine Integration** (3.12) — `CommunicationPipeline` gained `_run_decision_pipeline()`; `Persona.compose_reply()` now receives and weaves in a real `DecisionTrace`; `PersonaManager.select_from_context()` replaces the Level 2 keyword heuristic as the primary persona-switching signal; `main.py` constructs and registers all six Level 3 modules alongside Level 1+2's existing graph (15 modules total).
- **Error Handling & Recovery Hardening** (3.13) — the Fail Gracefully Rule applied across Level 3's six named failure scenarios (Ollama unreachable, ChromaDB unavailable, confidence-scoring edge cases, lifecycle cleanup partial failure, Authority Evaluator internal failure, Decision Engine pipeline failure) — `AuthorityEvaluator.evaluate()` now fails safe-down to `INFORM` on any internal error, and a Decision Engine pipeline failure degrades to `decision_trace=None` (a spoken, Level-2-quality reply) rather than ending the session.
- **Integration Testing & Level Freeze** (3.14) — a full Level 3 Acceptance Pass (`tests/system/test_level3_acceptance.py`): one continuous scripted conversation exercising memory storage/recall, the User Override Rule, confidence-band-driven lifecycle cleanup, real Context-Analysis-driven persona switching, and a simulated critical resource alert, all through a real `CoreManager` with the entire Level 1+2+3 graph; all six Sprint 3.13 hardening scenarios re-confirmed at the system level; an adversarial re-read of every `memory/`/`decision/` source file; a separate, opt-in real-model verification pass (`tests/system/test_level3_real_model_verification.py`) against a real running Ollama instance and ChromaDB's real embedding model.

## Verification

608+ unit/integration/system tests passing, `ruff check .` clean. Real, non-mocked verification was performed at multiple points:

- Every Level 3 unit test uses a real `MemoryStore` (real SQLite file + real ChromaDB, real embedding model) — no mocking of persistence anywhere in the Memory Engine or Dynamic Memory test suites, matching the "real save, real reload" convention established since Level 2's `ConversationSessionStore`.
- Sprint 3.11's own completion report confirmed the full Part 2 pipeline (Intent Detection → Context Analysis → Memory Retrieval → Priority Evaluation → Authority Evaluation → Engine Selection) end to end with a real Ollama call feeding a real Chroma/SQLite store, in one live run.
- Sprint 3.12's real composition-root smoke run: all 15 Level 1+2+3 modules reached `RUNNING` with passing health checks; a real conversation turn ("Help, there is a fire in the kitchen!") correctly produced the honest `RECOMMEND`-not-`EMERGENCY_ASSIST` degrade through the fully-wired pipeline.
- Sprint 3.14's opt-in real-model verification pass ran successfully against a real local Ollama instance (model `llama3` — this environment's Ollama installation only has `llama3:latest` pulled, which is why `ModelConfig.ollama_model`'s shipped default was changed to `"llama3"` this release, see Notable Bugs Found and Fixed) and ChromaDB's real embedding model: `IntentDetector`/`ContextAnalyzer` produced sensible classifications for a small set of example inputs (one deliberately ambiguous example — "remind me to call mom" — was classified `MEMORY_RECALL` rather than the initially-expected `ACTION_REQUEST`, a defensible read for a general-purpose, non-fine-tuned model, accepted as reasonable prompt-tuning feedback rather than a bug); real Chroma embedding search correctly ranked semantically related content above unrelated content.
- The committed, fast test suite (unit/integration/system) fakes only the Ollama boundary (`LanguageModelClient`) and the mic/wake/STT/TTS hardware/ML boundary inherited from Level 2 — Chroma/SQLite are real throughout, since neither has an external-service dependency the way Ollama does.

## Notable Bugs Found and Fixed During This Level

- **`MemoryStore`'s SQLite operations (`store()`'s INSERT, `get_by_id()`, `recent()`, `update_confidence()`, `delete()`) had no failure handling at all**, unlike this class's own Chroma-failure handling and its Level 2 sibling `ConversationSessionStore`'s SQLite handling — found during Sprint 3.14's adversarial re-read. `store()` now raises a typed `MemoryStoreError` on a genuine write failure (a caller receiving back a fake record id for a row that was never persisted would be worse off than an explicit error); the read/update/delete paths degrade gracefully (`None`, `[]`, or a logged no-op) matching this project's established Fail Gracefully convention. See [sprint_3_14.md](../sprint_book/sprint_3_14.md).
- **`PriorityQueueManager`'s resource-alert path (`classify_resource_alert()`/`.enqueue()`/`.pop_next()`/`.peek_next()`) and `ResourceMonitor.critical_alerts()` have zero live caller anywhere** — fully implemented and unit-tested in isolation since Sprint 3.10, but never actually invoked by the real turn-processing path. `docs/STATUS.md` previously overstated this as "wired"; corrected as part of this sprint's documentation pass. See `docs/backlog/technical_debt.md` item 17 — the same "implemented and tested in isolation, no live caller" bug class as item 11 (`ConversationSessionStore.purge_older_than()`).
- **A real, reproducible test-infrastructure timing race** (Sprint 3.12): Level 3's added startup latency (a real `MemoryStore`/Chroma initialization) exposed pre-existing timing assumptions in `tests/system`/`tests/integration`'s own fixtures — fixed via increased margins and a wake-detection call-counter reset technique, plus a module-registration-order fix in `main.py` (Level 3 modules now register after `communication_pipeline`, preserving the tight Level-2-only gap between `wake_word_detector` and the pipeline wiring).
- **`ModelConfig.ollama_model`'s shipped default changed from `"gemma3"` to `"llama3"`** — `"gemma3"` was never actually pulled on this project's own development machine, only `"llama3:latest"` was; every real-Ollama verification since Sprint 3.7 had to pass `ollama_model="llama3"` explicitly to work at all. Changed only after explicit user confirmation, once Sprint 3.14's real-model verification pass confirmed `llama3` classifies real conversational input correctly. See `docs/backlog/technical_debt.md` item 16 (resolved).

## Known Deferred Work

- **No periodic-task infrastructure exists before Level 4** — `MemoryLifecycleManager.run_cleanup_pass()`/`run_monthly_review()` (item 15) and `ConversationSessionStore.purge_older_than()` (item 11) both run only once at startup, not on a real recurring cadence; `PriorityQueueManager`'s resource-alert path (item 17, found this sprint) has no live caller at all. All three are the same underlying gap and are recommended to be resolved together once Level 4's Scheduler (Sprint 4.8+) exists.
- `AuthorityEvaluator`'s `approved_emergency_procedures` whitelist ships structurally empty — `EMERGENCY_ASSIST` is unreachable until Level 4's Device Control sprint (4.1) populates it with real, reviewed procedure ids, a deliberate, reviewed act per Sprint 3.11's own Future Considerations.
- The shipped wake phrase remains `hey_jarvis` (carried over from Level 2, item 5) — unaffected by this Level's work.
