# 0.4.1 — Runtime Stability & Internet Layer Refactor

**Not a semver git tag** — matching `0.3.1-level4-part-a.md`'s own precedent for a significant, real change that isn't itself a Level-closing milestone. Applied on top of `v0.4.0`'s own still-untagged work (Level 4 itself remains gated on the outstanding manual real-machine verification named in `sprint_4_20.md`'s own completion report).

Date: 2026-08-01
Driven by a direct, explicit user engineering brief (not a numbered Sprint Book sprint) covering three production-blocking/hardening issues, in priority order.

## Summary

Three issues, investigated and resolved in the order the brief itself specified. **Issue 1 (highest priority)**: a real, confirmed production-blocking crash — PySide6 and Coqui TTS could not coexist in the same process, meaning the real application's GUI and speech engine could never both work. Root-caused precisely (a PySide6/shiboken6 global import hook racing a real gap in the `six` package's own Python 3.12 compatibility, only ever exercised because of that hook) and fixed with the safest option in the brief's own preferred order — an import-order fix, no version pinning or architecture change needed. **Issue 2**: the Internet Agent no longer depends on any single commercial search provider — a real, ordered multi-provider fallback chain (Tavily → SearXNG → Brave by default) now tries each provider in turn, degrading to a structured, per-provider explanation only if every one fails. **Issue 3**: a real, personal command allow-list (common developer tools) is now configured, while `config/defaults.yaml`'s own shipped default stays empty/secure for everyone else.

## What Shipped

- **Issue 1 — PySide6 ↔ Coqui TTS runtime conflict, resolved.** `main.py` now imports `ui.app` locally, inside `main()`, immediately after a new `_prewarm_tts_before_pyside6()` call that imports `TTS.api` first — guaranteeing `six.moves` (and everything else Coqui TTS transitively needs) is cached in `sys.modules` before PySide6's own import hook is ever installed. The identical fix applied to a new `tests/conftest.py` (confirmed directly that its own top-level code runs before pytest-qt's own PySide6 import) fully resolves `backlog/technical_debt.md` item 29 — all 17 of `tests/unit/voice/test_text_to_speech.py`'s own tests pass now, not 2 of 17. Verified end-to-end with a real `QApplication`, a real Coqui model load (109 speakers), and a real `speak()` call producing real audio, all in one process.
- **Issue 2 — provider-agnostic Internet layer with real fallback.** `InternetConfig.search_providers: list[str]` (new, additive, default `["tavily", "searxng", "brave"]`) names an ordered chain; `internet/search_provider_registry.py`'s new `create_search_provider_with_fallback()` builds a real `internet/multi_search_provider.py`'s `MultiSearchProvider`, itself a `SearchProvider` Protocol implementer so `ResearchEngine` needs zero changes. Two new real providers: `internet/tavily_search_provider.py` (new `tavily_api_key` field) and `internet/searxng_search_provider.py` (reuses the already-generic `search_base_url` field). A provider failure falls back to the next automatically; every provider failing raises a new, structured `AllProvidersFailedError` (per-provider name + reason), already handled by `ResearchEngine.research()`'s own existing, unmodified degrade-to-empty-list behavior. `create_search_provider()`/`search_provider` (single-provider mode) are fully preserved for backward compatibility.
- **Issue 3 — a real, personal command allow-list.** `config/local.yaml` (git-ignored, never committed) now configures `device_control.approved_commands` with common developer tools (`code`, `python`/`python3`, `explorer`, `cmd`, `powershell`, `pwsh`, `wt`, `notepad`, `calc`, `taskmgr`, each with its real Windows executable/shim name too) — `config/defaults.yaml`'s own shipped default stays empty, unaffected, secure-by-default for anyone else. `system_command`'s own existing `HIGH` risk classification still requires a real, spoken confirmation for every invocation regardless of allow-list membership — a second, independent layer, not replaced by this change.

## Notable Findings During This Work

- **Issue 1's root cause was more precise than previously understood.** `backlog/technical_debt.md` item 29 (logged at Sprint 4.13) had already correctly identified the crash signature but had not previously confirmed it also broke the real running application (only the test suite was checked at the time) — confirmed directly in this session (`import PySide6.QtWidgets` then `import TTS` reliably crashes; the reverse order does not) before writing any fix, per the brief's own explicit "investigate first" instruction.
- **Five real, well-known public SearXNG instances were tried live in this session** for Issue 2's own verification — all five returned either a bot-detection challenge page, HTTP 429 (rate limited), or were unreachable. This is real, concrete evidence (not assumption) that public SearXNG instances are broadly unreliable for automated JSON API access; `search_base_url` deliberately defaults to nothing, requiring a real, deliberate choice (ideally self-hosted) rather than this project silently picking one on the user's behalf.
- **DuckDuckGo's official Instant Answer API returned exactly one general-search result** for a common, unambiguous query ("Python programming language") when called live in this session — confirming, with real evidence, that it is not a general web search API and not a reliable foundation for this project's own research use case. See `backlog/technical_debt.md` item 35.
