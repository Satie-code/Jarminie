## Summary

JARMINEI can now hold a real voice conversation: a wake phrase brings it out of Quiet Mode, real speech is transcribed, a persona (Jarvis or Minie) composes and speaks a reply, the conversation is remembered turn-by-turn, and the system returns to Quiet Mode on silence. Persona switching — by explicit request or a crude topic heuristic — happens mid-conversation with no simultaneous personas. Real language understanding and response generation are not yet implemented; `compose_reply()` is a deliberate, honestly-labeled placeholder until Level 3's Decision Engine (Sprint 3.7+).

## What Shipped

- **Voice Pipeline** (2.1–2.6) — `MicrophoneManager` (passive/active/muted mode gate), `WakeWordDetector` (openWakeWord), `WhisperSpeechToText`, `CoquiTextToSpeech` (dual voice, real VCTK speaker IDs picked by ear), `VoiceSessionManager` (turn cycle + inter-turn/intra-utterance timing), `QuietModeController` (the dormant/active state machine enforcing the Microphone Rule).
- **Conversation Engine** (2.7–2.8) — `SqliteClient` (the first generic `database/` piece, reused by Level 3), `ConversationSessionStore` (persisted, bounded-retention turn log), `ContextManager` (a pure aggregator — no inference, by design).
- **Persona Engine** (2.9–2.11) — `Persona` ABC, `JarvisPersona`/`MiniePersona`, `PersonaManager` (Part 2's full priority-ordered switching mechanism — Explicit Selection and Context Detection wired; Critical Emergency and Daily Routine named but reserved for Level 3/4).
- **Communication Pipeline Integration** (2.12) — `CommunicationPipeline` wires all of the above into one real system; `main.py` constructs and registers the full 9-module graph via `CoreManager`, the first real exercise of Level 1's composition-root pattern at scale.
- **Error Handling & Recovery Hardening** (2.13) — the Fail Gracefully Rule applied across six specific failure scenarios (microphone disconnect, STT/TTS failure, wake-word thread death, persona reply failure, persistence failure), each with a dedicated regression test.
- **Integration Testing & Level Freeze** (2.14) — a full Level 2 Acceptance Pass: a new system-test tier (`tests/system/`) driving one continuous scripted conversation through a real `CoreManager` with the entire module graph registered; every hardened failure scenario re-confirmed at the integration level; an adversarial re-read of every `voice/`/`personas/` source file.

## Verification

289 unit/integration/system tests passing, `ruff check .` clean. Real, non-mocked verification (not just fakes) was performed at multiple points:

- Real openWakeWord, Whisper, and Coqui models loaded and exercised individually per-sprint (2.1–2.5).
- A real `main.py` composition smoke run (Sprint 2.12): all 9 modules reached `RUNNING` on startup (~13–15s measured) and `STOPPED` cleanly on shutdown, using real models and a real microphone.
- A second real smoke run (Sprint 2.14) drove one complete conversation turn through the Sprint 2.13/2.14-hardened code paths specifically, with real components throughout: real microphone capture → real Whisper transcription (correctly produced empty text for silence, confirming the Sprint 2.3/2.5 hallucination-suppression fix still holds) → real Jarvis persona reply composition → real SQLite persistence → real Coqui synthesis, played through the actual system speakers. Shutdown mid-session also exercised the real cleanup path, including `CallbackRelay` safely no-op'ing once disconnected.
- The committed, fast test suite (unit/integration/system) uses fakes only at the audio-hardware/ML boundary — the same precedent established since Sprint 2.1, kept for CI feasibility (real model loads take too long for routine runs).

## Notable Bugs Found and Fixed During This Level

Several real bugs surfaced only through real end-to-end or adversarial testing, not by mocked unit tests alone — each documented as a "Post-Sprint Fix" on the sprint file that owns the affected code, per this project's established pattern:

- **`WakeWordDetector`'s background thread never stopped reading microphone frames once a session went active** (found by Sprint 2.12's integration testing), silently competing with `VoiceSessionManager`'s own utterance capture for the same audio stream. Fixed: the listen loop now pauses while the microphone isn't in passive-listening mode. See [sprint_2_2.md](../sprint_book/sprint_2_2.md#post-sprint-fix-2026-07-17-during-sprint-212).
- **`CommunicationPipeline._handle_turn_complete()` had no exception handling at all**, and neither did anything upstream of it — any unexpected failure anywhere in the turn-processing chain would silently kill the session's background thread rather than ending the session gracefully (Sprint 2.13).
- **`WhisperSpeechToText`/`CoquiTextToSpeech`'s `health_check()` could report healthy even after a real inference/synthesis crash**, since the loaded model object itself survives a failed call — fixed with a `_healthy` flag, the same pattern already established by `MicrophoneManager` (Sprint 2.13).
- **`ConversationSessionStore.get_recent_turns()` had no failure handling**, unlike `record_turn()` — found only by an adversarial *integration* test for a different scenario (a write failure), since the read path it actually exercised was different from the one named. A broken connection there aborted the entire turn instead of degrading to "no context available" (Sprint 2.13).
- **`QuietModeController.activate()` could get stuck believing it was `ACTIVE` with no real session running** if `begin_session()` failed in a narrow window — found during Sprint 2.14's adversarial re-read. See [sprint_2_6.md](../sprint_book/sprint_2_6.md).
- **`ConversationSessionStore.purge_older_than()` had no failure handling at all** (also found during the Sprint 2.14 re-read) — hardened proactively even though nothing calls it yet. See [sprint_2_7.md](../sprint_book/sprint_2_7.md).

## Known Deferred Work

- **A live, human-voice wake-word-to-spoken-reply round trip on the actual target laptop has not been performed.** This is the one Level 2 acceptance criterion no automated test can satisfy — a person needs to actually say the wake phrase and confirm the spoken reply. Sprint 2.14's own Acceptance Criteria name this explicitly as outside any Sprint Book automation's reach. **The `v0.2.0` git tag has not been created**, deliberately — per that same sprint's ordering ("performed... before tagging the release"), tagging is deferred until this manual step happens.
- `ConversationSessionStore.purge_older_than()` still has no live caller anywhere in the codebase (`backlog/technical_debt.md` item 11) — Sprint 2.7 predicted a caller would arrive at Sprint 2.12's integration, but 2.12's actual spec never asked for one. A periodic-timer mechanism is Scheduler-shaped functionality Level 2 explicitly excludes; deferred to a future Scheduler sprint (4.8+) or wherever a concrete retention-cleanup need is first observed.
- No automatic driver detects a wake-word thread dying during a long dormant period with no session active to react to (Sprint 2.13's own finding) — `restart_module()` recovers it correctly when invoked, but nothing invokes it automatically yet. Recommended as a scoped candidate for a Level 6 (6.2 Reliability) health-watchdog component, not built speculatively here.
- The shipped wake phrase remains `hey_jarvis` (openWakeWord's pretrained stand-in), not the product's intended "hey jarminei" — training a custom model is offline ML work outside any coding sprint (`backlog/technical_debt.md` item 5).
