## Level 3 — Intelligence (target: v0.3) — ✔ RELEASED

| Phase | Status |
|---|---|
| 3.1 Memory Engine | Complete — all four sprints done (3.1 Memory Store Foundation, 3.2 Shared Memory & Persona Memory, 3.3 Event Memory, 3.4 Short-Term Memory); see [sprint_book/INDEX.md](sprint_book/INDEX.md). `memory/memory_store.py`'s `MemoryStore` provides dual-backend (SQLite + ChromaDB) store/retrieve/delete for all five `MemoryType`s (including per-record `occurred_at`); `memory/persona_scoped_memory.py`'s `PersonaScopedMemory` enforces Shared/Jarvis/Minie's read-scoping rule structurally; `memory/event_memory.py`'s `EventMemory` guarantees permanent, undeletable milestones by construction; `memory/short_term_memory.py`'s `ShortTermMemory` promotes salient conversation turns into scored, session-tagged records — now with a real live caller (Sprint 3.12) instead of just the placeholder keyword heuristic sitting unused. All five memory layers now have real storage and per-type retrieval — Phase 3.1's "Memory stored correctly. Retrieval accurate." criteria met at the per-type level. |
| 3.2 Dynamic Memory | Complete — both sprints done (3.5 Confidence Scoring Engine, 3.6 Memory Lifecycle Manager); see [sprint_book/INDEX.md](sprint_book/INDEX.md). `memory/confidence_scorer.py`'s `ConfidenceScorer` implements the full five-factor Dynamic Memory Formula and the User Override Rule (an un-overridden record's score caps at 80/Long-term by design — only an explicit override or Event Memory's `is_permanent` flag reach Permanent); `memory/lifecycle_manager.py`'s `MemoryLifecycleManager` turns bands into real behavior — `run_cleanup_pass()` deletes past-grace-period Temporary records, `run_monthly_review()` surfaces Monthly-review-band records for a human with zero automatic mutation, `apply_user_override()` persists the User Override Rule. Sprint 3.12 gave both `run_cleanup_pass()`/`run_monthly_review()` (via `start()` itself, registered after `MemoryStore` in `main.py`) and `detect_override_phrase()`→`apply_user_override()` (via the live turn path) their first real callers — still a one-time-at-startup cadence for the former, not a periodic one (`backlog/technical_debt.md` items 11, 15; real recurring cadence remains deferred to Level 4's Scheduler). **This closes all of Level 3's Memory Engine/Dynamic Memory component sprints (3.1–3.6).** |
| 3.3 Decision Engine | Complete — all five sprints done (3.7 Intent Detection, 3.8 Context Analysis, 3.9 Memory Retrieval Engine, 3.10 Priority Queue, 3.11 Authority Evaluation & Engine Selection); see [sprint_book/INDEX.md](sprint_book/INDEX.md). `decision/intent_detector.py`'s `IntentDetector` classifies a transcript + `ConversationContext` (2.8) into an `Intent` via a real Ollama LLM call (`decision/llm_client.py`'s `OllamaClient`, behind the model-independent `LanguageModelClient` protocol), degrading to a safe `UNKNOWN` intent on any failure — never raising, never blocking a live turn. `decision/context_analyzer.py`'s `ContextAnalyzer` deepens that into topic/entities/suggested persona/a coarse sentiment hint — `ContextAnalysis.suggested_persona` is now the real, live-wired replacement for `PersonaManager.detect_context_heuristic()`'s keyword placeholder (Sprint 2.11), via `PersonaManager.select_from_context()` (Sprint 3.12); the heuristic itself remains as a fallback for when the Decision Engine pipeline is entirely unavailable. `memory/retrieval_engine.py`'s `MemoryRetrievalEngine` composes Sprints 3.1-3.6's memory layers into one ranked, explainable query (Part 2's "Memory Retrieval" pipeline stage), blending Chroma similarity with Sprint 3.5's confidence scores. `decision/priority_queue.py`'s `PriorityQueueManager` implements Part 2's full five-level Priority Queue System with the full five-level enum and classification logic in place, but only one source is actually wired into the live turn-processing path: `classify(intent)` (Intent-based tentative emergency flagging), called from `CommunicationPipeline._run_decision_pipeline()`. `ResourceMonitor` gained a real critical-severity signal for this sprint (`core/resource_monitor.py`'s `ResourceAlert`/`critical_alerts()`) and `PriorityQueueManager.classify_resource_alert()`/`.enqueue()`/`.pop_next()`/`.peek_next()` are implemented and unit-tested — corrected here from an earlier overstatement that called this "wired": nothing in the real pipeline actually calls any of them yet, the same "implemented and tested in isolation, no live caller" gap as `ConversationSessionStore.purge_older_than()` (found by Sprint 3.14's adversarial re-read, tracked as [backlog/technical_debt.md](backlog/technical_debt.md) item 17). Scheduler and Wellness sources remain reserved, unwired by design. `decision/authority.py`'s `AuthorityEvaluator` closes the pipeline: Part 2's three-level Authority System (a default-deny, whitelist-gated `EMERGENCY_ASSIST` that is structurally unreachable at Level 3 since zero emergency procedures are approved anywhere yet) and Engine Selection (always `CONVERSATIONAL_RESPONSE`/`INFORM_ONLY` at Level 3, with a `DecisionTrace`/`explain()` giving every decision a real, human-readable justification — the Explainability Rule's own deliverable). The shipped `ollama_model` default was `"gemma3"` through Sprint 3.11's own real verification (which had to pass `"llama3"` explicitly since `"gemma3"` was never pulled on this dev machine) — changed to `"llama3"` after Sprint 3.14's real-model verification pass confirmed it classifies correctly; see [backlog/technical_debt.md](backlog/technical_debt.md) item 16 (resolved). **This closes all of Level 3's Decision Engine component sprints (3.7-3.11) and, combined with 3.1-3.6, all of Level 3's individual-component sprints.** |

**Sprint 3.12 (Decision Engine Integration) wires the entire Level 3 graph built above into one real system**, mirroring exactly what Sprint 2.12 did for Level 2: `voice/pipeline.py`'s `CommunicationPipeline` gained a new `_run_decision_pipeline()` step (Intent Detection → Context Analysis → Memory Retrieval → Priority Evaluation → Authority Evaluation) running on every real conversation turn, with the resulting `DecisionTrace` now flowing into `Persona.compose_reply()` (its signature grew the anticipated `decision_trace: DecisionTrace | None` parameter, Sprint 2.9's own Risks flagged this exactly) and into `PersonaManager.select_from_context()` for real persona switching. `main.py` now constructs and registers all six of Level 3's `ManagedModule`s (`MemoryStore`, `MemoryLifecycleManager`, `IntentDetector`, `ContextAnalyzer`, `PriorityQueueManager`, `AuthorityEvaluator`) alongside Level 2's existing graph — 15 modules total. Verified for real, end-to-end, with no fakes at all (real Whisper, real Coqui, real openWakeWord, real Ollama, real Chroma/SQLite): all 15 modules reach `RUNNING` with passing health checks, and a real conversation turn ("Help, there is a fire in the kitchen!") correctly triggers the honest `RECOMMEND`-not-`EMERGENCY_ASSIST` degrade through the fully-wired pipeline. A real, reproducible test-timing race was found and fixed along the way (Level 3's added startup latency exposed a pre-existing assumption in `tests/system`/`tests/integration`'s own fixtures that wake-word detection and session timeouts had comfortable margin against fixture setup time — see `sprint_3_12.md`'s own completion report). **Sprint 3.13 (Error Handling & Recovery Hardening) applied the Fail Gracefully Rule across Level 3's six named failure scenarios**, mirroring Sprint 2.13's role for Level 2. The notable finding: four of the six scenarios (Ollama unreachable, ChromaDB unavailable, confidence-scoring edge cases, one corrupted record during memory lifecycle cleanup) were already correctly handled by production code shipped in earlier sprints (3.1, 3.5, 3.6, 3.7/3.8) — this sprint's job for those four was adding real-induced-failure regression tests proving it, not new production code. Two scenarios did need real changes: `decision/authority.py`'s `AuthorityEvaluator.evaluate()` now wraps its own body in a try/except, failing safe-down to `AuthorityLevel.INFORM`/`EngineSelection.INFORM_ONLY` on any internal error rather than ever defaulting to something more permissive; `voice/pipeline.py`'s `CommunicationPipeline._handle_turn_complete()` now gives its Decision Engine pipeline call its own narrower exception boundary, degrading to `decision_trace=None` and letting the turn still complete with a spoken reply instead of ending the whole session, as it did before this sprint. Full detail, including why `main.py`/`decision/llm_client.py` needed no changes despite being named in the sprint's own Files to Modify, in `sprint_3_13.md`'s own completion report.

**Sprint 3.14 (Integration Testing & Level Freeze) formally closes Level 3 — Intelligence and Release v0.3.** A full Level 3 Acceptance Pass confirmed Phase 3.1 ("Memory stored correctly. Retrieval accurate."), 3.2 ("Scores update correctly. Memory lifecycle functions."), and 3.3 ("Correct subsystem selected. Explainability preserved.") together, via: a new `tests/system/test_level3_acceptance.py` driving one continuous scripted conversation (a "remember this" fact triggering the User Override Rule, a Context-Analysis-driven persona switch, a technical follow-up whose reply reflects the overridden memory, a simulated critical resource alert, and a direct `run_cleanup_pass()` confirming the overridden memory survives while an unrelated stale fixture record is correctly removed) through a real `CoreManager` with the entire Level 1+2+3 graph; all six Sprint 3.13 hardening scenarios re-confirmed at the system level; an adversarial re-read of every `memory/`/`decision/` source file that found and fixed a real gap (`MemoryStore`'s SQLite operations had no failure handling at all, unlike its own Chroma-failure handling — see `sprint_3_14.md`'s own completion report) and one documentation-accuracy gap (`PriorityQueueManager`'s resource-alert path has no live caller despite this file previously claiming otherwise — corrected above, tracked as `backlog/technical_debt.md` item 17); and a separate, opt-in real-model verification pass (`tests/system/test_level3_real_model_verification.py`) that ran successfully against a real local Ollama instance (model `llama3`) and ChromaDB's real embedding model. 623/623 tests passing (617 fast + 6 opt-in real-model, run separately), `ruff check .` clean.
